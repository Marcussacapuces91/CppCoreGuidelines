# <a name="s-cpl"></a>CPL : programmation de style C

C et C++ sont des langages étroitement liés.
Ils dérivent tous deux du « C classique » de 1978 et ont évolué au sein des comités ISO depuis lors.
De nombreuses tentatives ont été faites pour maintenir leur compatibilité, mais aucun n'est un sous-ensemble de l'autre.

### <a name="rcpl-c"></a>CPL.1 : Préférer C++ à C

##### Justification

C++ offre un meilleur contrôle des types et un meilleur support notationnel.
Il offre un meilleur support pour la programmation de haut niveau et génère souvent un code plus rapide.

##### Exemple

    char ch = 7;
    void* pv = &ch;
    int* pi = pv;   // non C++
    *pi = 999;      // écrase sizeof(int) octets près de &ch

Les règles de conversion implicite vers et depuis `void*` en C sont subtiles et non appliquées.
En particulier, cet exemple viole une règle interdisant la conversion vers un type avec un alignement plus strict.

##### Application

Utiliser un compilateur C++.

### <a name="rcpl-subset"></a>CPL.2 : Si vous devez utiliser C, utilisez le sous-ensemble commun de C et C++, et compilez le code C en tant que C++

##### Justification

Ce sous-ensemble peut être compilé avec des compilateurs C et C++, et lorsqu'il est compilé en tant que C++, il bénéficie d'un meilleur contrôle des types que le « C pur ».

##### Exemple

    int* p1 = malloc(10 * sizeof(int));                      // non C++
    int* p2 = static_cast<int*>(malloc(10 * sizeof(int)));   // non C, C++ de style C
    int* p3 = new int[10];                                   // non C
    int* p4 = (int*) malloc(10 * sizeof(int));               // C et C++

##### Application

* Émettre un avertissement si le mode de compilation traite le code comme du C.

  * Le compilateur C++ s'assurera que le code est un C++ valide, à moins que vous n'utilisiez des options d'extension C.

### <a name="rcpl-interface"></a>CPL.3 : Si vous devez utiliser C pour des interfaces, utilisez C++ dans le code appelant qui utilise de telles interfaces

##### Justification

C++ est plus expressif que C et offre un meilleur support pour de nombreux types de programmation.

##### Exemple

Par exemple, pour utiliser une bibliothèque C tierce ou une interface système C, définissez l'interface de bas niveau dans le sous-ensemble commun de C et C++ pour un meilleur contrôle des types.
Dès que possible, encapsulez l'interface de bas niveau dans une interface qui suit les directives C++ (pour une meilleure abstraction, une meilleure sécurité mémoire et une meilleure gestion des ressources) et utilisez cette interface C++ dans le code C++.

##### Exemple

Vous pouvez appeler C depuis C++ :

    // en C :
    double sqrt(double);

    // en C++ :
    extern "C" double sqrt(double);

    sqrt(2);

##### Exemple

Vous pouvez appeler C++ depuis C :

    // en C :
    X call_f(struct Y*, int);

    // en C++ :
    extern "C" X call_f(Y* p, int i)
    {
        return p->f(i);   // éventuellement un appel de fonction virtuelle
    }

##### Application

Aucune nécessaire.
