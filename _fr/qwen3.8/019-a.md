### <a name="ra-stable"></a>A.1 : Séparer le code stable du code moins stable

Isoler le code moins stable facilite son test unitaire, l'amélioration de son interface, son refactoring et sa dépréciation éventuelle.

### <a name="ra-lib"></a>A.2 : Exprimer les parties potentiellement réutilisables sous forme de bibliothèque

##### Raison

##### Remarque

Une bibliothèque est un ensemble de déclarations et de définitions maintenues, documentées et livrées ensemble.
Une bibliothèque peut être un ensemble d'en-têtes (une « bibliothèque en-têtes uniquement ») ou un ensemble d'en-têtes accompagné d'un ensemble de fichiers objets.
Vous pouvez lier statiquement ou dynamiquement une bibliothèque à un programme, ou inclure une bibliothèque en-têtes uniquement via `#include`.


### <a name="ra-dag"></a>A.4 : Il ne doit pas y avoir de cycles entre les bibliothèques

##### Raison

* Un cycle complique le processus de compilation.
* Les cycles sont difficiles à comprendre et peuvent introduire de l'indéterminisme (comportement non spécifié).

##### Remarque

Une bibliothèque peut contenir des références cycliques dans la définition de ses composants.
