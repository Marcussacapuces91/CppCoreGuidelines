### <a name="ra-stable"></a>A.1 : Séparer le code stable du code moins stable

L'isolation du code moins stable facilite ses tests unitaires, l'amélioration de l'interface, le refactoring et sa dépréciation éventuelle.

### <a name="ra-lib"></a>A.2 : Exprimer les parties potentiellement réutilisables comme une bibliothèque

##### Raison

##### Remarque

Une bibliothèque est un ensemble de déclarations et de définitions maintenues, documentées et expédiées ensemble.
Vous pouvez lier statiquement ou dynamiquement une bibliothèque à un programme, ou bien vous pouvez `#include` une bibliothèque uniquement en en-tête.

### <a name="ra-dag"></a>A.4 : Il ne doit y avoir aucun cycle entre les bibliothèques

##### Raison

* Un cycle complique le processus de construction.
* Les cycles sont difficiles à comprendre et peuvent introduire de l'indéterminisme (comportement non spécifié).

Une bibliothèque peut contenir des références cycliques dans la définition de ses composants. Par exemple :
