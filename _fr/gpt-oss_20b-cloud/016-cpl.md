# <a name="s-cpl"></a>CPL: Programmation de style C

C et C++ sont des langages étroitement liés.  
Ils tirent tous deux leur origine du "Classic C" de 1978 et ont évolué dans les comités ISO depuis.  
De nombreux essais ont été faits pour les maintenir compatibles, mais aucun n'est un sous-ensemble de l'autre.

### <a name="rcpl-c"></a>CPL.1: Préférer C++ à C

##### Raison

C++ offre une meilleure vérification des types et un meilleur support notatoire.  
Il offre un meilleur support pour la programmation de haut niveau et produit souvent du code plus rapide.

##### Exemple

    char ch = 7;
    void* pv = &ch;
    int* pi = pv;   // pas C++
    *pi = 999;      // écraser sizeof(int) octets près de &ch

Les règles de conversion implicite vers et depuis `void*` en C sont subtiles et non appliquées.  
En particulier, cet exemple viole une règle interdisant la conversion vers un type avec un alignement plus strict.

##### Application

Utilisez un compilateur C++.

### <a name="rcpl-subset"></a>CPL.2: Si vous devez utiliser C, utilisez le sous-ensemble commun de C et C++, et compilez le code C en C++

##### Raison

Ce sous‑ensemble peut être compilé à la fois avec des compilateurs C et C++, et lorsqu'il est compilé en C++ est mieux vérifié en termes de types qu'un C pur.

##### Exemple

    int* p1 = malloc(10 * sizeof(int));                      // pas C++
    int* p2 = static_cast<int*>(malloc(10 * sizeof(int)));   // pas C, style C++
    int* p3 = new int[10];                                   // pas C
    int* p4 = (int*) malloc(10 * sizeof(int));               // à la fois C et C++

##### Application

* Marquer si le mode de construction compile le code en C.
  * Le compilateur C++ appliquera les règles C++ à moins d'utiliser des options d'extension C.

### <a name="rcpl-interface"></a>CPL.3: Si vous devez utiliser C pour les interfaces, utilisez C++ dans le code appelant qui utilise ces interfaces

##### Raison

C++ est plus expressif que C et offre un meilleur support pour de nombreux types de programmation.

##### Exemple

Par exemple, pour utiliser une bibliothèque C tierce ou une interface système C, définissez l'interface de bas niveau dans le sous‑ensemble commun de C et C++ pour une meilleure vérification des types.  
Chaque fois que possible, encapsulez l'interface de bas niveau dans une interface suivant les directives C++ (pour une meilleure abstraction, sécurité mémoire et sécurité des ressources) et utilisez cette interface C++ dans le code C++.

##### Exemple

Vous pouvez appeler C depuis C++:

    // en C:
    double sqrt(double);

    // en C++:
    extern "C" double sqrt(double);

    sqrt(2);

##### Exemple

Vous pouvez appeler C++ depuis C:

    // en C:
    X call_f(struct Y*, int);

    // en C++:
    extern "C" X call_f(Y* p, int i)
    {
        return p->f(i);   // appel d'une fonction virtuelle possible
    }

##### Application

Pas besoin
