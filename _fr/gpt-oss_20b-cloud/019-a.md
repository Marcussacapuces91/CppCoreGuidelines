### <a name="ra-stable"></a>A.1: Séparer le code stable du code moins stable

L'isolation du code moins stable facilite ses tests unitaires, l'amélioration de l'interface, le refactoring, et sa possible dépréciation.

### <a name="ra-lib"></a>A.2: Exprimer les parties potentiellement réutilisables comme une bibliothèque

##### Raison

##### Remarque

Une bibliothèque est un ensemble de déclarations et de définitions maintenues, documentées et livrées ensemble.

Une bibliothèque peut être un ensemble d'en-têtes (une « bibliothèque uniquement en en-têtes ») ou un ensemble d'en-têtes plus un ensemble de fichiers objets.

Vous pouvez la lier statiquement ou dynamiquement à un programme, ou bien vous pouvez `#include` une bibliothèque uniquement en en-têtes.

### <a name="ra-dag"></a>A.4: Il ne doit pas y avoir de cycles entre les bibliothèques

##### Raison

* Un cycle complique le processus de construction.
* Les cycles sont difficiles à comprendre et peuvent introduire de l'indéterminisme (comportement non spécifié).

##### Remarque

Une bibliothèque peut contenir des références cycliques dans la définition de ses composants.

Cependant, une bibliothèque ne doit pas dépendre d'une autre qui dépend d'elle.
